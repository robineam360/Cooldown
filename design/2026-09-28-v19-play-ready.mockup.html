Rev B, compared with rev A: every existing element is now drawn from the real code (About card, Updates card, Debug cards, error notice, status line), not invented. The crash card moves out of the swipeable account pages to above the account tabs, so it no longer repeats on every page. The buttons are in Material order ("Not now" then "Share report"). A crash with no trace can still be shared. System kills never show a card. The Settings tabs now scroll only when a title does not fit. A Crash reports card in Diagnostics lets you share a report you dismissed. The widget reconfigure section just points to the approved rev D view and draws nothing new.

The page follows your system theme. This control only switches the device frames.

1 · Main screen: the crash card on the next launch

This is CCRM-85 (Crash Capture). After a crash, the next launch shows one app-wide card directly under the top bar, above the account tabs. It sits outside the swipeable account pages, so it stays put while you swipe accounts and never appears twice. With one account there are no tabs, and the card sits above the usage cards. It never shows a trace, an email or an exception message.

Backing out of the sheet keeps the card.

2 · About card: Privacy policy

This is CCRM-89 (Privacy Policy). The About card stays exactly as it is, and one TextButton is added: Privacy policy, centred, 8 dp below "Share feedback" and 4 dp above the disclaimer (which moves down by 48 dp, since the button is a 48 dp touch target). A text button fits this centred card better than a divided list row. It opens docs/privacy.md on GitHub in the browser chosen in Settings, and the row is the same in both flavors. An on-screen link to the policy is allowed in the Play build; only update paths outside Play are not.

3 · Diagnostics and Debug: Crash reports and Crash now

Both sit behind the existing unlock (tap the version seven times), so a locked More tab looks exactly as it does today. Crash reports goes under "App log" in Diagnostics: it says how many reports are on file, with Share and Delete, and it is hidden when there are none. Crash now is the last card in Debug, for the Step 7 test. It uses an outlined button in the error colour, behind a confirm dialog. Its exception message carries a canary, a fake sk-ant-… token and an email address, so Step 7 proves the shared report leaves both out. That only tests that messages are excluded, so CCRM-85's unit tests also plant canaries in every field the report keeps and in sample ANR and native traces, and Step 7 checks both the saved file and the shared text. It is in both flavors, because Step 7 tests both.

4 · The Play build: no Updates card, no update action

This is CCRM-87 (Update Channel). The GitHub build is unchanged. The Play build drops the whole Updates section (its label, toggle, "Check for updates" button and last-checked line), so Polling and Usage credits run straight into About. On the inner screen the left column simply ends sooner. Also missing from the Play build, though never on screen unless triggered: the "Update available" notification, the strip in the pinned notification, and the "Open GitHub" dialog.

The invalid-response notice on the main screen

The title and detail are unchanged in both flavors. Only the action row differs: GitHub keeps "Check for updates" (it opens Settings), and Play has no action. The words "an app update may be needed" still hold on Play, where the update comes through the Play Store by itself.

5 · Settings tabs: CCBG-35 (Tab Clip)

Today: a fixed four-way TabRow. At 360 dp each tab gets 90 dp and "Appearance" clips to "Appearanc". At 2.0× all four clip. Proposed fix: keep the fixed row whenever every title fits its equal share at the current width and font scale, which leaves the cover and inner screens exactly as they are today. Otherwise switch to a ScrollableTabRow (edgePadding 0, 90 dp minimum). The fixed row keeps today's 10 dp a side on each title, and the fit test measures with that same 10 dp, so the cover screen at 1.0× stays fixed. The scrolling row uses 16 dp a side. A cost that is accepted: the main screen's account tabs switch on the number of accounts, deliberately, so that row never changes shape when the phone unfolds. This rule switches on fit instead, so at a large font scale the Settings row can be scrolling on the cover screen and fixed on the inner screen. Titles are never shortened or ellipsized, and the row grows taller at large font sizes instead of clipping. The selected tab scrolls into view when you tap it or swipe the page, and the edge of the next tab stays visible as a hint that the row scrolls.

6 · Widget reconfigure label: CCBG-48 (Reconfigure Label)

A restoration, nothing new to draw. The approved widget rev D (design/2026-09-25-widgets-reborn.html) already draws the reconfigure view as "Widget settings" with a Save changes button. Today the app chooses that label only when saved preferences exist, so a widget the launcher placed without config shows "Add widget" when you reconfigure it later. v1.9 bases the choice on whether the widget is already placed. The screen matches rev D exactly, so under CLAUDE.md §2's exemption it needs no new drawing.

CCBG-45 (Single Panel Wording) is the same kind of case. You ruled on 2026-09-27 that it is fixed as-is: the one-account notification takes the approved "5h" and "Weekly" wording. It is listed here so this page covers every visible v1.9 change.

7 · Reviews so far

A fresh Opus judge (Fable was out of credits) ruled "keep rev B" on all seven calls, with six concerns, all adopted: the "N reports" wording, a whitelist of exit reasons, no card after an upgrade, the landscape placement, 48 dp not 40, and the tab padding and unfold wording.
