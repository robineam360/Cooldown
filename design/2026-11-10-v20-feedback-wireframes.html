9. Sample mode on Android — "Try with sample data", for a reviewer with no accounts

Robin, 2026-11-10: "Port sample mode". Android gets the iPhone app's reviewer sample data (CCRM-94 (iOS App), design/2026-11-05-ios-parity-wireframes.html §7 rev B; ios/App/UI/SampleMode.swift). Only the Android delta is drawn. Marks: new a visible element Android does not have today; reused an existing element, unchanged or with different words. Before: Android has no way in without a provider account. Its only made-up data is the debug-only synthetic series of CCRM-15 (Above-Pace Verification), which overlays real accounts and keeps sign-in state real, so it is no use to a reviewer.

The rule, in one paragraph. Sample mode is a process-wide flag held in memory only, like SyntheticSeries. While it is on, the app's screens read three made-up accounts — Teams (Claude, Max), Personal (ChatGPT, Plus), Lab (Gemini, Pro) — with made-up readings and history. Every setting read and write goes to an in-memory copy seeded from the user's own. Nothing is written: no token, no account, no history, no display setting. Nothing is fetched or sent. The real registry, cache, history and settings are not touched, so real accounts come back exactly as they were.

  • new First screen (no account): 12 dp under the existing "No Claude account yet" card (MainActivity.kt:868), a text button "Try with sample data" (labelLarge 14 sp, the accent, 48 dp high) and the caption "Three made-up accounts to look around. Nothing is saved or sent." (bodySmall, muted). The card itself is unchanged.
  • new Add account sheet (Settings › Accounts › "+ Add account"): a last row under a divider — a 28 dp violet ring-and-dot glyph, "Try with sample data" (bodyLarge), the same caption (bodySmall). This is the only entry when real accounts exist. No confirmation dialog, as on iOS; the banner says what happened and Exit undoes it.
  • Entering lands on the All tab (three accounts, so the Summary exists). The copy is iOS's, word for word (SampleRules.entryTitle, entryDetail).

Isolation rules (Astra review, all four adopted; no visible change).
  • C1-1 · Real work keeps running. "Nothing is fetched or sent" is the sample's guarantee. Real accounts' background polling, reset checks and alerts carry on unchanged and write only the real stores, which is what keeps the real notification and widgets honest. A request in flight on entry completes into the real store. The sample never starts a fetch. Test: entering and exiting leave the registry, cache, history and preferences byte-identical apart from what real polling wrote.
  • C1-2 · Settings split by reader. Only the app's screens read and write the in-memory settings copy. notify/, widgets/, alerts/ and polling always read the real settings, so an Appearance change in the sample never reaches the notification or a widget. Test: change Appearance in the sample with the notification and a widget live; both keep the real settings.
  • C1-3 · No late write crosses over. Entering or leaving the sample dismisses any open dialog, sheet or menu and drops its pending edit. A sample edit is bound to the sample store when it opens, not looked up through the flag when it commits, so a commit that arrives late can only reach the sample copy, which is gone by then. Test: open Rename in the sample, launch a real account from the notification, and confirm the real name is unchanged.
  • C1-4 · The debug series pauses. Entering suspends the debug synthetic series if it is on, in memory. Exit restores it as it was. Neither state is written, and process death clears both, as today.
