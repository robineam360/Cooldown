CCRM-118 (Header Glyphs) — the consolidated wireframe, as Robin decided it on 2026-11-13

Fable (expertise), 2026-11-13. This page replaces, for approval, the four pages it consolidates: design/2026-11-13-tag-glyph-android-and-filter.html, -summary-header-glyphs.html, -tag-badge-styles.html, -tab-icon-tag-dot.html. The icon is the built RailIcon (ios/App/UI/InnerPanes.swift, CCBG-86 (Rail Marks Alike)), proven on the iPhone 17e bottom bar and the iPad landscape sidebar by the spike captures in design/research/2026-11-13-ccrm118/ (colour and badge kept, light and dark; the selected label tints, the icon does not). Drawn at 1 dp = 1 px (iOS 1 pt = 1 px), real numbers, generated from one icon function so every surface draws the same thing. The page follows your system's light / dark; panels marked light / dark are forced. Related: CCRM-110 (Account Tags), CCRM-115 (Row Tag Glyph), CCRM-116 (Inner Panes), CCRM-112 (Summary Snapshot).

0 · What this page builds (binding, Robin 2026-11-13)

  1. One account icon on every account tab: the provider mark in the account's accent, with the tag badge as built (B0 / F: a 13 disc cleared 1.5 wider out of the mark's lower-right corner, a filled person / briefcase in ink). Surfaces: iPhone bottom tab bar and its More list, iPad landscape sidebar, the Duo's cover rail, inner wide rail and tall bottom bar, Android's Main and History strips (phone, Fold 7 inner, tablet), the iOS History strip, the iOS account header. iPad portrait's top bar stays names only (accepted).
  2. The tag is never a colour. Ink figure, the disc is the surface, the accent means the account and the severity colours mean usage. Unchanged.
  3. New setting — "Tag marks", Personal on/off and Work on/off, default both on. It decides whether a tag's mark is drawn wherever the tag shows as a mark: every tab icon above, the Summary row glyph (full and one-line), the iOS account header, the snapshot's glyph column. It never touches the Settings tag chip, the Add sheet, the Tag dialog or the Summary filter segments (those set or pick the tag and always show both). Robin's own setting: Work on, Personal off — "if no briefcase, I'll know it's personal".
  4. Summary filter: "All" (a word, no count) · person N · briefcase N. An empty group keeps full ink with its 0; a tap shows today's 3 s note (E1). The words stay for TalkBack / VoiceOver.
  5. Sort button: always the current order's glyph — drag handle (your order) · ring 20 % (most room first) · timer (resets soonest) · ring 85 % (most used); the words only in the menu; the two rings are custom glyphs on both platforms. Android keeps its "wrap from font scale 1.5" rule.
Reading the three combinations. BOTH ON today's look, the default. PERSONAL OFF Robin's: Work accounts carry the briefcase, Personal accounts carry a plain mark. WORK OFF the mirror. BOTH OFF no mark anywhere; every account icon is the plain mark, the row glyph column is gone, the header is mark + name. Two things never move when a toggle flips: the mark's position inside its icon box (the badge is drawn or not; the mark stays at the box's top-left so a badged and an unbadged tab align), and the screen-reader label ("Teams, Work account" whether or not anything is drawn).

8 · The Summary header — filter as glyph + count, sort as a glyph

Control: "All" 35 dp (iOS 33) · person + digit 47 (45) · briefcase + digit 47 (45) = 133 dp (iOS 125), 140 with a two-digit count; glyph 16 dp × font scale in the control's ink, 4, the digit at 12 sp (13 pt) tabular; chosen segment tonal (13 %) and semibold, digit included. The count is the group's size among all accounts, never the rows shown. Sort: 50 dp (iOS 41), glyph 16 (14) in `onSurfaceVariant` (`txt`) + ▾; one width for every order. Line at 360 dp: 44 + 10 + 133 + 50 = 237 of 288 (51 spare); iPhone 17e 52 + 10 + 125 + 6 + 41 = 234 of 326. Android wraps the control under the title from font scale 1.5 (equal thirds); iOS `ViewThatFits` keeps two forms (one line, or title + sort over a full-width control). The filter segments always show both tags whatever Tag marks says.

9 · Summary rows — the row glyph under the setting, and the column rule with RowGlyphFit

Rule: the glyph column exists while any row shown has a tag whose mark is on. While it exists, every row shown keeps the slot (14 + 4 full, 12 + 4 one-line) — a row whose tag is off leaves its slot blank, so names align. When no row shown has a drawn mark (both off; or Personal off under the Personal filter; or Personal off and every account Personal — Robin's phone today), the column is absent and the name starts where the mark (full row) or the rank disc (one-line) ends. Then, and only then, the built drop rule runs unchanged: name to its 64 dp floor, then the column leaves every row at once, then the name ellipsizes on (one-line: bar floor 40 dp / 50 pt). In code: column = rows.any { marks[it.tag] } && RowGlyphFit.keepsGlyph(rows); re-decided on a width, filter, rows, display, font or Tag marks change.

10 · The snapshot's glyph column

Today: the column (12 box + 4, before the mark) only while the rows on the card carry both tags. Now: while the rows carry both tags and at least one of those tags is marked; a row whose tag is off leaves its slot blank, as on screen. So Robin's All snapshot with mixed accounts shows briefcases and blanks; his all-Personal install shares the card without a column, as today. The snapshot never runs the drop rule (fixed 300 pt / 360 dp card).

12 · Questions for Robin — one decision each, my answer first

  1. Where the setting lives. Appearance, after Summary order, shown with two or more accounts (§2) — the display settings' home, beside the two Summary rows it belongs with. Else at the top of Settings › Accounts above the cards (where the tags are set; then it shows with one account too).
  2. A mixed list with one tag off (Robin's: Personal off, All filter, Work and Personal rows together). Blank slot, column kept (§9): names align, the briefcases line up, nothing shifts when a row's tag changes. Else collapse per row (a Personal row's name starts 18 dp earlier than a Work row's — ragged).
  3. Rows on the Duo rail and the iPad sidebar when the setting hides a mark. The plain mark stays at the box's top-left (§1: nothing moves on a toggle). Else recentre the plain mark in its box (2 dp shift when the toggle flips; a Work and a Personal tab's marks then sit 2 dp apart).

  • Setting: UsageCache.tagMarks(): Map<AccountTag, Boolean> / setTagMark(tag, on), keys tagMarks.personal, tagMarks.work, absent = true; TagMarksGroup(cacheSettings) in SettingsScreen.kt after SummaryOrderGroup inside the same SummaryRank.tabShown block; the sample's MemoryPrefs copy.
