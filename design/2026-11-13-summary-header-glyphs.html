1 · The control as glyph + count

1.1 Anatomy — "All" a word, the groups a glyph and a count

All stays a word. The person and the briefcase are taught by every row underneath; nothing teaches a glyph for All (the All tab's three bars mean "the tab", and the prior page rejected three glyphs as cryptic). A count on All would be the sum of the other two, so it carries none; the row is uneven by 12 dp and that is the honest shape. The count is the group's size among all accounts, never the rows shown: under the briefcase filter the person segment still says 3. Glyph 16 dp in the control's ink (onSurface / ink), 4 dp, the digit at the segment's 12 sp (13 pt), tabular; the chosen segment tonal (13 % fill) and semibold — digit included.

1.2 The empty group — count 0: full ink, a button, the tap answers (recommended)

Three ways to draw a group with no accounts. E1 (recommended): the segment is drawn like the others — full ink, the digit 0 — and stays a Button; a tap shows today's line "No Work accounts yet. Tag one in Settings." under the header for 3 s and selects nothing. Nothing in BEHAVIOR-MOBILE §6 changes: the filter in force, the memory rule, SummaryFilters.enabled and SummaryFilter.resolve are untouched; only the 38 % alpha goes (and segmentsEnabled keeps steering the tap). E2: the 0 and the 38 % dim together — the same thing said twice, and a 12 sp digit at 38 % on the dark card is about 2 : 1 against its background, below any legibility floor, so the explanation is the part you cannot read. E3: the tap selects the empty group and the list shows the line as its empty state — honest, but the memory rule as written rewrites a stored value whose group is empty to all at once, so the choice bounces; keeping it needs a new rule, the shared fixture and both clients' tests.

E1 costs: the 38 % alpha and VoiceOver's "dimmed" go (TalkBack's "no accounts" state stays, now literally true); a segment that looks live and answers with a line instead of a filter — the 0 is what makes that honest. E2: an unreadable digit. E3: a new shared rule, the tags fixture and both clients' memory tests.

1.3 Counts — 1, 2, 10 accounts; both tags

One account: the Summary does not exist (§6: two or more accounts), so there is no header to draw. Two: the first state most users see after the upgrade. Ten: a two-digit count widens its segment by 7 dp; the control is at most 147 dp (two two-digit counts) — nothing on this page needs that width.

1.5 Variant — "All" with its count (not recommended)

Costs: a redundant number in a header that already competes with the figures column; it reads as a fourth statistic.

1.6 Font scale 1.5 and 2.0 (288 dp)

The glyph is 16 dp × font scale (so it never shrinks beside a large "All"), the digit scales as text; the control wraps under the title from scale 1.5 as today, its three segments sharing the width equally (today's 3 : 8 : 4 word weights are the words'; glyph + digit are the same width in every segment). The sort button on the title row is the glyph, so it never competes with the title. At scale 1.3 (Android "Large") the line still fits on one row: 57 + 10 + 151 + 55 = 273 of 288 (282 with a two-digit count).

2.2 The menu open — glyph + word per row, a check on the current

2.3 Telling the order from the closed button — against today

Today's words tell you the order without opening anything and the glyph will not until the menu has been opened once. Two things make the trade worth it: with glyph + count in the control the words no longer fit on a 360 dp phone for two of the four orders ("resets soonest" 301, "most room first" 304 of 288) while they fit for the other two — a measured rule would show words for "your order" and the ⇅ for "most room first", on the same phone; and the filter beside it is now glyph-only, so a word button next to it is the odd one out. The menu teaches the glyphs with words on the first open, as the Settings chips teach the person and the briefcase.

2.4 Alternative S2 — words where the widest order fits, the glyph where it does not

Measure "most room first ▾" (the widest, not the current one), so a width shows words for every order or for none and the button never changes form on a choice. Then: words on the Fold's inner column (304 ≤ 317), the cover (340), the iPad and every Duo pane; the glyph on 360 dp phones (288) and on 375-pt iPhones (312 > 311, by one point — UNVERIFIED); the 17e keeps words (312 ≤ 326). With a leading glyph before the words the button is 16 + 4 wider and the Fold column loses them again (324 > 317), so S2 is words without a glyph where they fit.

S2 costs: two looks for one button — Robin's own Fold shows words on the inner screen and the glyph on no screen he owns, so the glyphs would be seen only by 360 dp phones and large-text users; a measured rule on Android (a TextMeasurer pass like AddSheetTagControl's) replacing one constant; iOS already measures. Glyph-always costs: one open of the menu to learn four glyphs; the words are then in the menu, Appearance › Summary order and the screen readers only.

2.5 Rejected glyphs, one line each

  • Numbered list for Your order (SF list.number / Material format_list_numbered): says "order" well, but it is a glyph the app shows nowhere; the drag handle is on the Reorder sheet already. The fallback if the handle reads as a hamburger on the device pass.
  • Hourglass for Resets soonest (SF hourglass / Material hourglass_top): already used by the iOS widget for a window that is spent (LiveAndControl.swift), so it would mean two things.
  • Gauges for room / used (SF gauge.with.dots.needle.0percent / 100percent, iOS 17+; Material has only speed): a pair on iOS and a single on Android — two looks, and a car dial is not the app's meter.
  • Batteries (SF battery.100percent / battery.25percent, Material battery_full / battery_2_bar): a pair on both, but a battery reads "charge left", the inverse of the used-% ring the rows show.
  • Flame for Most used: not the app's register (Robin, 2026-09-09: professional, no mascots).
  • ↻ for Resets soonest: the footer's refresh glyph.
  • Arrows ↑ ↓ beside the ⇅ (ascending / descending): the four orders are not two directions of one key.

5 · Questions for Robin — one decision each, my answer first

  1. "All". A word, no count (§1.1). Else "All 5" (§1.5).
  2. The empty group. E1: full ink, the 0, a button, the tap answers with today's 3-s note; no rule change. Else E2 (dim kept) or E3 (the tap selects an empty list; a new shared rule and fixture).
  3. The four glyphs. Drag handle · ring 20 % · timer · ring 85 % (§2.1). Else swap the handle for the numbered list, or the timer for the hourglass.
  4. The closed sort button. Glyph always, words only in the menu (§2.3). Else S2: words where "most room first" fits, the glyph under that (§2.4).
  5. Where the two rings come from. Two custom symbols in the iOS asset catalog and two vector drawables on Android, so the menu rows and the button use the same glyph on each platform. Else SF gauges on iOS and drawn rings on Android (two looks).
  6. The wrap rule on Android. Keep "from font scale 1.5" (one constant, tested, and the measured line agrees at 288 dp). Else measure the line as iOS does.
  7. Tracker. A new item, CCRM-118 (Header Glyphs), citing CCRM-110 (Account Tags) and CCRM-115 (Row Tag Glyph), in v2.0 with the tab glyph of the prior page's Problem 1 — the header is what you see every day. Else an amendment under CCRM-110 (Account Tags), which is Built and device-check pending.
